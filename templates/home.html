Under the hood

Built like infrastructure, not a demo

The console is the part clients see. Underneath, it's the same architecture a property would run on year one, not a one-off script for a pitch.

VOICE
Calls are carried over Twilio ConversationRelay, with a dedicated FastAPI service handling the real-time audio stream.
HEARING
Speech is transcribed as the guest talks using Deepgram, so the agent can respond mid-sentence instead of waiting for a pause.
REASONING
Requests are understood and routed by a Groq-served LLM, tuned to each agent's prompt, tools, and property.
RECORD
Bookings, transcripts, and call metadata are written to a Django + DRF backend the console reads from live.
TENANCY
Every property is a separate tenant by design — one hotel's agents, calls, and bookings never touch another's.
Before you ask

A few things clients want to know

Does the agent replace the front desk, or back it up?

It's built to back it up. The agent takes the call the moment staff can't — overnight, mid-check-in, or during the dinner rush — and logs everything so a human is never picking up a conversation blind.

What happens when a guest asks for something the agent can't do?

The call is logged with the full transcript and flagged for follow-up, so nothing gets silently dropped — staff see exactly what was asked and can call the guest back.

How long does setup take for a new property?

Configuring an agent — its prompt, tools, and voice — takes minutes in the console. Connecting a phone number through Twilio is the only step outside the app.

Is one hotel's data ever visible to another?

No. Deskline is multi-tenant by design — agents, calls, and bookings are scoped to a property from the database up, not just filtered in the UI.
